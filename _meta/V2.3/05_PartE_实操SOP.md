# Part E · 实操 SOP（标准作业程序）

> **本 Part 是 V2.3 新增。**
> Part A 告诉你"流水线 11 步是什么、每步学什么"；本 Part 告诉你"真要做一部作品时，每步先做什么、再做什么、做到什么程度算合格"。
> 粒度：**中**——比 Part A 详细，但不绑死任何具体软件版本与按钮路径（那一层放在 `repo/sop_templates/` 中的工艺规范里，随软件迭代更新）。
> 每步统一七段式：**前置 / 调用知识库 / 调用 Agent / 调用工具 / 操作动作 / 产出落点 / 质检要点**。

---

## 阅读约定

- **【前置】**：本步开始前必须已完成的事；不满足就别开始。
- **【调用知识库】**：本步需要读哪些 Part A-D 文档 / 哪些 `repo/knowledge_base/` 笔记。
- **【调用 Agent】**：本步主要由哪个 LLM 智能体（Part D 编号 A1-A11）承担。**⚠️ 标记表示该 Agent 暂未编写实体 system prompt，当前可用 `repo/sop_templates/` 中的模板手动操作。**
- **【调用工具】**：本步用什么软件/服务（写作工具、AI 绘图、视频生成、剪辑软件等）。
- **【操作动作】**：3-7 个有序步骤，每步动作具体到可执行。
- **【产出落点】**：本步结束后产物存到项目目录的哪个文件夹（对应 `_template/` 中的路径）。
- **【质检要点】**：本步过关的几条硬标准；不过关不进入下一步。

## E.0 项目初始化

**【前置】**：脑子里有了一个想做的题材方向（哪怕只是一句话）。

**【调用知识库】**：
- `_meta/V2.3/00_README.md` 索引
- `_meta/V2.3/01_PartA_学习路线.md` 流水线全貌

**【调用 Agent】**：无（纯手动）。

**【调用工具】**：文件管理器 / 命令行 / git。

**【操作动作】**：
1. 在 `06_项目作品/` 下复制 `_template/` 为新目录，命名 `XX_作品名/`（XX 为两位序号，如 `01_未命名玄幻短篇/`）。
2. 打开 `XX_作品名/00_企划.md`，填写：题材方向一句话、目标时长、目标平台、个人学习目标。
3. 打开 `XX_作品名/SOP_checklist.md`，确认 11 步 checkbox 都是未勾选状态。
4. `git add` 整个新作品目录、`git commit -m "init 作品名 项目骨架"`。

**【产出落点】**：`06_项目作品/XX_作品名/`（完整骨架已就位）。

**【质检要点】**：
- ✅ `00_企划.md` 至少填了题材方向、目标时长、目标平台三项；空着不算开工。
- ✅ 目录结构与 `_template/` 完全一致，不要在初始化阶段就魔改目录。

- ✅ 主投平台只选 1-2 个，不要"全平台通吃"。

## E.2 步骤 1 + 1.5 · 小说大纲与精化

**【前置】**：E.1 完成；`00_企划.md` 已定稿。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 1、1.5
- `04_PartD_Agent体系.md` 中 A1-A4 的 Schema

**【调用 Agent】**：
- ⚠️ A1 大纲 Agent（待编写）
- ⚠️ A2 正文 Agent（待编写）
- ⚠️ A3 精化 Agent（待编写）
- ⚠️ A4 审查 Agent（待编写）

**【调用工具】**：DeepSeek Chat（主力）+ 手动二次润色。

**【操作动作】**：
1. **A1 大纲**：把企划的三幕拆解扩成章节大纲（短篇 5-10 章，每章 200 字梗概）。存 `01_小说/大纲.md`。
2. **A2 正文**：按大纲逐章生成正文（每章 1500-3000 字）。**逐章生成、逐章检查**，不要一次让 AI 写完全本。存 `01_小说/正文.md`。
3. **A3 精化**：对正文做语言风格统一、人物口吻区分、场景描写补充。存 `01_小说/精化.md`。
4. **A4 审查**：检查逻辑漏洞、时间线矛盾、人物设定前后不一致。审查报告存 `01_小说/审查.md`，问题逐条标注章节行号。
5. 根据审查报告回炉修改 A3 产物，直到审查通过。

**【产出落点】**：`XX_作品名/01_小说/` 下四个文件齐全。

**【质检要点】**：
- ✅ 大纲每章梗概必须含"本章核心冲突 + 章末钩子"。
- ✅ 正文不允许出现"她做了一个深呼吸"这种 AI 套话占比 > 5%。
- ✅ 审查报告若仍存在"未解决"问题，禁止进入步骤 2。
- ✅ 总字数与企划阶段定的目标时长大致匹配（参考：1 分钟成片 ≈ 200-300 字小说量，按你的口播节奏校准）。

## E.3 步骤 2 · 剧本拆分（标准 + 精简）

**【前置】**：E.2 全部完成且审查过关。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 2
- `repo/sop_templates/` 中的剧本格式规范（如果已建）

**【调用 Agent】**：
- A6 标准剧本 Agent
- A7 精简剧本 Agent
- A8 连贯性审查 Agent
- **并行**：⚠️ A5 设定集 Agent（待编写）可以与 A6 并行启动，从小说中抽人物/场景/物品。

**【调用工具】**：DeepSeek Chat。

**【操作动作】**：
1. **A6 标准剧本**：把小说精化版改写成标准剧本格式（场号 / 内外景 / 时间 / 角色 / 对白 / 动作 / 镜头建议）。存 `02_剧本/标准剧本.md`。
2. **A7 精简剧本**：基于标准剧本，按目标时长砍场——保留主线、删支线、合并冗余场景。存 `02_剧本/精简剧本.md`。
3. **A8 连贯性审查**：精简后检查"删除某场是否导致后续场景断逻辑"。审查报告存 `02_剧本/连贯审查.md`。
4. **并行 A5（可选）**：让设定集 Agent 同步从小说中抽取人物清单/场景清单/物品清单，先出"清单"不出"形象"——形象等步骤 3 再精修。临时落点 `04_素材/_临时_设定清单.md`。
5. 若 A8 发现断逻辑，回炉 A7 重剪，直到通过。

**【产出落点】**：`XX_作品名/02_剧本/` 下三个文件齐全；`04_素材/_临时_设定清单.md`（可选）。

**【质检要点】**：
- ✅ 标准剧本每场必须有场号、内外景、时间、出场角色四要素。
- ✅ 精简剧本总场数 × 平均场时长 ≈ 目标成片时长（误差 ±15%）。
- ✅ 连贯审查无"未解决"项。
- ✅ 精简版砍掉的场景，必须在审查报告里说明"砍它不影响主线"的理由。

## E.4 步骤 3 · 设定集精修（人物 / 场景 / 物品）

**【前置】**：E.3 完成；步骤 2 并行抽取的清单（若有）已就位。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 3
- `repo/knowledge_base/` 中的"角色三视图规范"、"场景设定卡模板"笔记

**【调用 Agent】**：⚠️ A5 设定集 Agent（待编写）。

**【调用工具】**：DeepSeek / Claude（文本设定）+ AI 绘图工具（人物形象，参考步骤 4b 同套工具）。

**【操作动作】**：
1. **人物设定卡**：每个出场角色出一张卡（外貌关键词、性格、口头禅、服装、年龄、与他人关系）。
2. **角色三视图**：主要角色用 AI 绘图生成正面 / 侧面 / 背面统一画风的三视图，作为后续分镜的角色锚定参考。存 `04_素材/角色三视图/{角色名}/`。
3. **场景设定卡**：主要场景（5-15 个）出文字描述卡 + 1-2 张代表性参考图。
4. **物品/道具卡**：关键道具单独建卡（特别是反复出现的）。
5. 整合：把所有设定卡汇总到一个总览文件，方便步骤 4 分镜时查阅。

**【产出落点】**：
- `XX_作品名/04_素材/角色三视图/{角色名}/{正,侧,背}.png`
- `XX_作品名/04_素材/` 根目录的 `设定集总览.md`（汇总所有卡片）

**【质检要点】**：
- ✅ 主要角色三视图必须画风一致（同一模型、同一 LoRA、同一提示词模板）。
- ✅ 每个角色的外貌关键词在卡里要写死（用于后续分镜复用），不能每次分镜重新发明。
- ✅ 场景卡至少覆盖剧本中出现 ≥ 2 次的所有场景。

## E.5 步骤 4a + 4b · 分镜与关键帧

**【前置】**：E.3、E.4 都完成。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 4
- `repo/knowledge_base/` 中的"镜头语言基础"、"AI 绘图提示词工程"笔记

**【调用 Agent】**：⚠️ A9 分镜 Agent（待编写）。

**【调用工具】**：
- 4a 分镜表：DeepSeek/Claude 生成 + 表格软件维护
- 4b 关键帧：Midjourney / Stable Diffusion / NovelAI / 即梦 / 文心一格 等 AI 绘图工具（按你已选定的主力工具）

**【操作动作】**：
1. **4a 分镜表生成**：基于精简剧本，每场拆 1-N 个镜头，列出：镜号 / 景别（远中近特）/ 角度 / 镜头运动 / 画面描述 / 时长（秒）/ 对应角色 / 对应场景 / AI 绘图提示词草稿。存 `03_分镜表.md`。
2. **4b 关键帧生成**：按分镜表逐镜出图。每镜出 4-8 张候选，挑 1 张定稿。
3. 角色一致性把控：每次绘图都引用 E.4 的角色三视图作为参考（IP-Adapter / Reference / 垫图）。
4. 场景一致性把控：同一场景的多个镜头复用相同的场景关键词模板。
5. 定稿图按命名规则归档：`{场号}_{镜号}_{描述}.png`。

**【产出落点】**：
- `XX_作品名/03_分镜表.md`
- `XX_作品名/04_素材/关键帧/{场号}/`

**【质检要点】**：
- ✅ 分镜表每行必填镜号、景别、画面描述、时长四项。
- ✅ 同角色在不同镜头中的脸不能"飘"——抽查 5 张同角色图，画风/五官应能一眼认出是同一人。
- ✅ 每镜定稿前必须出 ≥ 4 张候选，不能"第一张就定"。
- ✅ 所有镜头时长加总 ≈ 目标成片时长（误差 ±10%）。

## E.6 步骤 5 · 图生视频

**【前置】**：E.5 关键帧全部定稿。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 5
- `repo/knowledge_base/` 中的"图生视频工具对比"、"运镜提示词"笔记

**【调用 Agent】**：⚠️ A10 视频化 Agent（待编写）。

**【调用工具】**：可灵 / 即梦 / Runway / Pika / Luma / Vidu / Sora 等图生视频工具（按你选定的主力）。

**【操作动作】**：
1. 按分镜表逐镜把关键帧送进图生视频工具，配上运镜与动作提示词（推、拉、摇、移、固定 + 角色具体动作）。
2. 每镜生成 2-3 个版本，挑最自然的一版定稿（特别关注：手部、面部、文字、物理一致性这四类高翻车区）。
3. 不合格的镜头：先尝试改提示词重生成；连续失败 3 次的，考虑改回静态关键帧 + 后期加动效（Ken Burns / 局部动画）。
4. 视频片段按命名规则归档：`{场号}_{镜号}_{描述}.mp4`，保持与关键帧同名以便对照。

**【产出落点】**：`XX_作品名/04_素材/视频片段/{场号}/`

**【质检要点】**：
- ✅ 每镜定稿前至少出 2 个版本对比，不能"一次出一个就用"。
- ✅ 角色脸部在镜头内不允许"换脸"——抽查 3 段视频，定睛看每一帧人脸是否稳定。
- ✅ 手部明显畸形 / 多指 / 文字乱码的镜头必须重生成或弃用。
- ✅ 视频总时长加总 ≈ 目标成片时长（误差 ±10%）。

## E.7 步骤 5.5 + 5.6 · 配音 / 配乐 / 字幕

**【前置】**：E.6 视频片段就位（不要求全部完成，可与 E.6 并行后半段）。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 5.5、5.6
- `repo/knowledge_base/` 中的"AI 配音工具对比"、"BGM 版权与素材库"笔记

**【调用 Agent】**：⚠️ A11 音频 Agent（待编写）。

**【调用工具】**：
- 配音：ElevenLabs / Fish Audio / 魔音工坊 / 剪映文本朗读 / 自录
- BGM/音效：Suno / Udio / 站酷海洛 / 爱给网 / YouTube 音频库

**【操作动作】**：
1. **配音**：基于精简剧本的对白部分，逐角色生成配音。每个角色固定一个音色，不要每集换。导出按场号/镜号命名。

**【质检要点】**：
- ✅ 同一角色全片音色一致，不允许中途换嗓。
- ✅ 字幕错字率 < 1%，标点符合中文规范（不要英文逗号混入）。
- ✅ BGM 与画面情绪匹配；不要全片一个 BGM 拉到底。
- ✅ 配音整体响度大致一致（不出现某段特别小声需要观众调音量）。

## E.8 步骤 6 · 剪辑成片

**【前置】**：E.6（视频片段）+ E.7（音频、字幕）全部就位。

**【调用知识库】**：
- `01_PartA_学习路线.md` § 步骤 6
- `repo/knowledge_base/` 中的"剪辑节奏与转场"、"调色基础"笔记

**【调用 Agent】**：无（剪辑目前以人工为主，AI 仅辅助）。

**【调用工具】**：剪映专业版 / Premiere / DaVinci Resolve / CapCut（按你的主力工具）。

**【操作动作】**：
1. **粗剪**：按分镜表顺序把视频片段串起来，初步对齐配音（先卡时间线）。
2. **精剪**：调整每镜入出点，砍冗余、加节奏。重点关注开头 3 秒（决定完播率）和高潮段（决定分享率）。
3. **配 BGM + 音效**：分段铺 BGM、关键动作加音效，做好音量混音（人声 > BGM）。
4. **加字幕**：导入 SRT 或在剪辑软件内做样式化字幕（字体、描边、底色统一）。
5. **调色 + 特效**：统一色调（不一定要复杂调色，但全片基调要一致）；按需加转场、特效。
6. **首尾包装**：开场 logo/标题、结尾片尾（订阅引导 / 下集预告）。
7. **导出**：按目标平台规格导出（抖音 1080×1920 竖屏 / B站 1920×1080 横屏 / 自定）；同时保留工程文件。

**【产出落点】**：
- `XX_作品名/05_工程/`（剪辑软件工程文件）
- `XX_作品名/06_成片/{作品名}_v{版本号}.mp4`

**【质检要点】**：
- ✅ 开头 3 秒必须有钩子（悬念 / 冲突 / 反差），不允许"今天给大家带来"这种开场。
- ✅ 字幕字体、大小、位置全片统一，不要中途换样式。
- ✅ 人声响度始终高于 BGM 至少 6dB（混音基本要求）。
- ✅ 导出后实际播放一遍，确认无黑屏、无音画不同步、无字幕错位。
- ✅ 版本号管理：每次重大修改导出新版本（v1 / v2 / v3），不要覆盖。

**【调用工具】**：

- 数据：各平台原生数据后台 + 自建 Excel/Notion 追踪表

**【操作动作】**：
1. **发布前准备**：起标题（钩子型）、写简介（含关键词）、选封面（高对比 + 短文字）、打标签、设置定时发布。
2. **多平台分发**：按主投平台规格导出对应版本（横竖屏、时长裁切）；不同平台标题/封面可微调。
3. **首发 24 小时**：定时回评论、置顶关键评论、观察播放完成率与完播曲线。
4. **3-7 天数据复盘**：记录核心指标（播放、完播率、点赞率、评论率、转发率、涨粉），对照发布前的预期。

- `XX_作品名/07_复盘.md`（本作品的复盘）

**【质检要点】**：
- ✅ 发布后必须做 3-7 天数据复盘，不允许"发完就完事"。
- ✅ 复盘笔记必须含"下作品的 3 条具体改进项"，不要空泛的"以后要更好"。
- ✅ 至少 1 条复盘洞察要回填到知识库（项目级 → 仓库级的知识转移）。

## E.10 跨步纪律（贯穿全流程）

以下规则贯穿 E.0-E.9，不属于单步：

1. **每完成一步，勾选 `SOP_checklist.md` 对应 checkbox**——这是项目进度的唯一真实来源（不是凭印象）。
2. **每完成一大步（E.2、E.3、E.5、E.6、E.8）做一次 git commit**，提交信息格式：`[作品名] 完成步骤X：xxx`。
3. **质检不过关不进下一步**——这是 SOP 的核心；跳步会在后续步骤翻倍补债。
4. **AI 产物必须人工二次审阅**——大纲、正文、剧本、分镜的 AI 输出全部人工过一遍，不能直接进入下一步。
5. **关键决策记入 `00_企划.md` 的"决策日志"段**（如：为什么换主投平台、为什么砍掉某条支线、为什么换 AI 绘图工具）。
6. **不要在项目目录里魔改工艺规范**——工艺层的更新（如新的提示词模板、新的工具用法）应该回到 `repo/knowledge_base/` 或 `repo/sop_templates/`，由后续作品继承。

## E.11 异常处理与回退

| 异常情况 | 处理方式 |
|---|---|
| 某步质检反复不过关 | 不要硬上，回退到上一步重做（如分镜不过关常常是因为剧本场太碎）。 |
| AI 工具大版本更新导致风格突变 | 当前作品坚持用旧版本完工；新版本评估后写入知识库，留给下作品。 |
| 平台政策变化（如不能投某类题材） | 在 `00_企划.md` 决策日志中记录、调整发布平台或题材方向，不要硬投赌封号。 |
| 项目跨度过长想暂停 | 在 `07_复盘.md` 头部记录"暂停于步骤 X，原因 Y，恢复条件 Z"，commit 后即可放下。 |
| 想推翻重做 | 不要删除现有目录；新建 `XX_作品名_v2/` 平行目录，原版作为"经验沉淀"保留。 |
