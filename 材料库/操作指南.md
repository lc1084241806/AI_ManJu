# AI 漫剧 Agent 操作指南

> 给"用 agent 跑流水线"的实操手册。**所有人第一次跑流水线之前必读**。
>
> 本指南只讲怎么用,不讲 agent 内部规则(那些在每个 agent 文件里)。
>
> 配套文档:
> - 流水线总览:`材料库/agent/README.md`
> - 各阶段 SOP:`材料库/SOP/`
> - 各 agent system prompt:`材料库/agent/A1...F1.md`

---

## §1 核心概念(一定要懂)

### §1.1 agent 文件 = system prompt

`材料库/agent/<编号>_<名称>.md` **整个文件**就是要喂给大模型的 **system prompt**。

不是 user message,不是参考文档,**就是系统提示词**。

| 客户端 | system prompt 填在哪里 |
|---|---|
| DeepSeek Web | 暂时没有官方 system 字段,**整文贴到第一条 user message,然后下一条才发任务材料** |
| Claude Web(claude.ai) | 点 Project → Custom Instructions / Project Knowledge → 贴整文 |
| Claude API | `system` 字段 |
| 豆包 / Kimi | 智能体设置 → System Prompt → 贴整文 |
| Cursor / Cline | 工具的 system 配置项,或建一个本地 agent |

### §1.2 user message = 任务材料

system prompt 告诉模型"你是谁、怎么做",**user message** 告诉模型"这次的任务材料是什么"。

例:用 A3 精化第 5 集——
- system prompt:`A3_小说精化.md` 整文(只贴 1 次)
- user message:
  ```
  本集 A2 小说正文(第 5 集):
  <第 5 集原文……>

  世界圣经.md:
  <世界圣经全文……>

  A1 大纲:
  <A1 大纲全文……>
  ```

### §1.3 一次会话 = 一个任务

**不同 agent 必须开新会话**。

错误用法:同一个对话窗口,先让模型当 A2,再让它当 A3,再当 B1。结果:模型记忆漂移,会用 A2 的口吻做 A3 的事。

正确用法:跑 A3 时开新对话 → 跑 B1 又开新对话 → 跑 C1 又开新对话。**每个 agent 一个对话窗口**。

### §1.4 跨章长期记忆 = 世界圣经.md

模型本身没记忆——你今天让它精化第 1 章,明天让它精化第 2 章,它根本不记得第 1 章发生了什么。

解决方案:**世界圣经.md**(模板见 `材料库/世界圣经模板.md`,放在 `我的作品/<作品名>/世界圣经.md`)。

- A2 初次执行时**创建**世界圣经种子
- A3 每集精化后**追加增量**到世界圣经
- 后续每个 agent 在 user message 里**强制带上世界圣经全文**

## §2 流水线节奏(关键!)

> 问题:整本一次喂入会超上下文,每章独立跑又会跨章不连贯。
> 解决:**不同阶段用不同粒度,跨章一致性靠世界圣经维护**。

### §2.1 粒度速查表

| 阶段 | 单次喂入粒度 | 跨次记忆载体 | 单次最大 |
|---|---|---|---|
| A1 大纲 | 一次性出全集 | — | 1 次 |
| A2 小说正文 | **per 1-3 集** | 世界圣经 + 已生成集 logline 摘要 | 3 集 |
| A3 小说精化 | **per 1 集** | 世界圣经 + A1 大纲 | 1 集 |
| A4 内容审查 | **per 5 集**(批审) | 世界圣经 + A1 大纲 | 8 集 |
| B1 剧本生成 | **per 1 集** | 世界圣经 | 1 集 |
| B2 剧本精简 | **per 1 集** | 世界圣经 | 1 集 |
| B3 剧本连贯审 | **per 5 集**(批审) | 世界圣经 + A1 大纲 | 8 集 |
| C1 分镜骨架 | **per 1 集** | 世界圣经 | 1 集 |
| C2 分镜增强 | **per 1 集** | 世界圣经 | 1 集 |
| C3 分镜审查 | **per 1 集** | 世界圣经 | 1 集 |
| D1 视觉设定集 | **全局一次**(阶段 A 模板 + 阶段 B 7 批次) | A3 资产卡 + 风格包 | 阶段 B 一次一批 |
| D2 视觉设定集审 | 全局一次 | D1 输出 | 1 次 |

### §2.2 实操串接示例(一个 16 集作品的完整跑法)

```
Day 1
  □ A1 选题 + 大纲 → 全 16 集大纲(1 次)
  □ A2 初始化 → 世界圣经种子 + 第 1-3 集小说
  □ A3 精化第 1 集 → 更新世界圣经
  □ A3 精化第 2 集 → 更新世界圣经
  □ A3 精化第 3 集 → 更新世界圣经

Day 2-5
  □ 重复 A2 → A3 循环,每天写 3 集精化 3 集
  □ 每 5 集跑一次 A4(第 5 集后审第 1-5 集 / 第 10 集后审第 6-10 集 / 第 15 集后审第 11-15 集 / 第 16 集后审 16)

Day 6
  □ 16 集小说全部精化完毕 + A4 全审过
  □ B1 第 1 集 → B2 第 1 集
  □ B1 第 2 集 → B2 第 2 集
  □ ...每集独立跑 B1+B2,每天 4-5 集

Day 7-8
  □ B3 每 5 集一审

Day 9
  □ D1 阶段 A 一次定型(整本作品的画风/题材模板,只跑 1 次)
  □ D1 阶段 B 7 批次(元素清点 → 人物 → 兵器 → 神兽 → 法宝 → 道具 → 场景)
  □ D2 审查 D1 输出

Day 10-11
  □ 逐集跑 C1 → C2 → C3(每集独立会话)

Day 12+
  □ D3 / E1 / F1(以后再建 agent)
```

## §3 标准启动语模板

每个 agent 在新会话里的"第一条 user message"模板。**复制粘贴改字段即可**。

### A1 大纲

```
请按你的 system prompt 工作,生成一部作品的全集大纲。

题材:战神 / 总裁 / 修仙玄幻 / 重生穿越 / 古风宫斗 / 复仇 / 甜宠言情 / 现代都市 / 悬疑 / 恐怖 (从这 10 个里选 1 个)
集数:16
每集时长:180s
画风:国漫CG_老师标准(从 材料库/画风/ 选)
平台:抖音

我的核心想法 / 角色 / 情节:
<把你脑子里想的故事讲清楚,3-10 句>
```

### A2 小说正文(首次)

```
请按你的 system prompt 工作。本次首次执行,请初始化世界圣经,并生成第 1 集小说正文。

A1 完整大纲:
<贴 A1 输出>

本次要生成的集编号:第 1 集

世界圣经:首次执行,请初始化
```

### A2 小说正文(后续)

```
请按你的 system prompt 工作。本次生成第 4-5 集小说正文。

A1 完整大纲:
<贴 A1 输出>

本次要生成的集编号:第 4-5 集

世界圣经:
<贴 世界圣经.md 全文>

前序集 logline 摘要(已生成集):
- 第 1 集:<1-2 句>
- 第 2 集:<1-2 句>
- 第 3 集:<1-2 句>
```

### A3 小说精化

```
请按你的 system prompt 工作。本次精化第 3 集。

本集 A2 小说正文:
<贴第 3 集 A2 原文>

世界圣经:
<贴 世界圣经.md 全文>

A1 大纲:
<贴 A1 输出>
```

### A4 内容审查

```
请按你的 system prompt 工作。本次批审第 1-5 集。

平台:抖音
题材:战神
批次:第 1-5 集

本批 A3 精化版:
<贴第 1-5 集 A3 输出>

世界圣经:
<贴 世界圣经.md 全文>

A1 大纲:
<贴 A1 输出>
```

### B1 剧本生成

```
请按你的 system prompt 工作。本次生成第 1 集剧本。

本集 A3 精化版(第 1 集):
<贴第 1 集 A3 输出>

世界圣经:
<贴 世界圣经.md 全文>

题材:战神
平台:抖音
每集时长:180s
```

### B2 / B3 / C1 / C2 / C3

参照各 agent 文件的 §输入约定。结构都是「本集材料 + 世界圣经 + 上下文字段」。

### D1 / D2

详见 `材料库/SOP/故事板SOP.md` §3-§5。D1 跑法特殊(阶段 A 一次性 + 阶段 B 七批次,每批一次会话)。

## §4 常见错误自救

### Q1. 模型主动续写、问"是否要下一章"

**原因:** agent 的 §0 行为约束 没生效。检查 system prompt 是否完整贴进去。

**自救:** 回一句「按 §0 行为约束,只处理本轮输入,不主动续写。」如果反复出现,重开会话重新贴 system prompt。

### Q2. 模型输出 HTML / JSON / 大段代码块包裹

**原因:** agent §0 输出格式 没生效(同上)或模型默认习惯。

**自救:** 回「按 §0 输出格式,只用 Markdown,禁止 HTML / 整文代码块。请重新输出。」

### Q3. 模型跨集失忆,把第 5 集的角色写错(性别/相貌/能力)

**原因:** 你没把世界圣经喂进去,或喂的是旧版本。

**自救:** 每次新会话,从 `我的作品/<作品名>/世界圣经.md` 复制**当前最新版**到 user message。每跑完一个 agent 都要更新世界圣经。

### Q4. 模型输出半截就停 / 被截断

**原因:** 模型单次输出上限到了(DeepSeek/Claude 一般 8k-16k token)。

**自救:** 回「继续,从 <断点处> 接着输出」。或者降低本次输入规模(比如 A2 从 3 集改成 1 集)。

### Q5. 模型不按 schema 输出(漏字段、加多余字段)

**原因:** 模型自由发挥。

**自救:** 回「请严格按 §输出 Schema,补全 <缺失字段>,删除 <多余字段>。」如果反复,可以把 §输出 Schema 那段单独再贴一遍强化。

### Q6. 模型把 agent 当聊天机器人

例:用 A3 时,模型说「您好,请问需要我帮您精化哪部分?」

**原因:** system prompt 没生效。

**自救:** 检查 system 字段是否真的填了。DeepSeek Web 版没有官方 system 字段,必须用「第一条 user message 贴 system prompt → 第二条 user message 发任务材料」的方式。

### Q7. 题材模块不匹配(写战神但模型按古风模板生成)

**原因:** 题材字段没传或传错。

**自救:** 启动语里**显式指定**题材,严格从 10 个枚举里选(战神 / 总裁 / 修仙玄幻 / 重生穿越 / 古风宫斗 / 复仇 / 甜宠言情 / 现代都市 / 悬疑 / 恐怖)。

### Q8. 模型把多个 agent 的能力混在一起

**原因:** 在同一个对话窗口先后切换了多个 agent system prompt。

**自救:** **每个 agent 一个新对话窗口**,不要在一个对话里切角色。

## §5 客户端推荐

### 桌面优先(主力)
- **DeepSeek Web**:免费 + 上下文足够。**注意没有官方 system 字段**——用"第一条 user message 贴 system prompt"workaround
- **Claude Web(claude.ai Project)**:Custom Instructions 支持 system,质量最好,有用量限制
- **Cursor / Cline**:本地 agent + 可调 system,适合做高级流水线

### 手机次选(临时跑)
- **DeepSeek App**:能用,但贴 system prompt 体验差
- **Claude iOS / Android**:支持 Project,体验和 Web 一致
- **豆包 / Kimi**:智能体功能能存 system prompt,适合手机临时跑

### 强烈不建议
- 任何"AI 助理一句话生成"型产品(扣字数、丢上下文)
- ChatGPT 不带 Project / 不带 GPTs 的 free tier(系统字段不可控)

---

## §6 三个铁律

1. **system prompt 整文贴**——不要节选,不要"省略一些规则"。每个字都是设计过的。
2. **每个 agent 一个新对话**——别复用对话窗口。
3. **世界圣经永远是最新的**——每次跑完更新,每次开始喂入最新版。

违反任意一条,流水线就会崩。

## §8 反馈
