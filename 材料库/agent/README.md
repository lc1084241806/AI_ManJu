# Agent 库

> AI 漫剧流水线 10 步中,有 7 步可以**标准化**成可复用的 LLM 系统提示词(system prompt)——这就是 16 个 Agent(A1-F1,按流水线顺序连号;A5 阅读版导出为旁路工具)。
> 把它们配置到 DeepSeek / Claude / 豆包,**输入对应素材就能直接出活儿**,不用每次重新写指令。
>
> **第一次跑流水线之前先看 `材料库/操作指南.md`**——讲怎么填 system prompt、怎么传任务材料、怎么避免模型串戏。
>
> **跨章长期记忆机制**:见 `材料库/世界圣经模板.md`。所有 per-集 跑的 agent(A2/A3/B1/B2/C1/C2/C3)都需要把世界圣经作为输入之一,防止模型跨集失忆。
>
> **修订记录**:见 `材料库/agent/CHANGELOG.md`(已从各 agent 文件抽离,避免污染 system prompt)。

## Part 1 · Agent 是什么、为什么要拆

### 1.1 一句话定义

**Agent** = 一份**喂给 LLM 创建智能体的 system prompt**(.md 文件),让 LLM 在某个生产环节扮演特定角色、用特定方式干活。

**不是项目规则**(CLAUDE.md 那种"和 Claude 协作的工作目录规则")。
**不是对话指令**(临时发的 prompt)。
**是可复用、可版本化、可在不同平台间迁移的工作流**。

### 1.2 为什么把流水线拆成多个 agent,而不是写一段长 prompt 一气呵成

| 长 prompt 一气呵成 | 拆成多个 agent |
|---|---|
| 上下文窗口爆炸 | 每个 agent 只看自己该看的输入 |
| 一处错全盘崩 | 一处错只改一处 |
| 跨平台难复用 | 同一 agent 可跑 DeepSeek / Claude / 豆包 |
| 无法版本化 | 文件即版本,可入 git,可对比 diff |
| 难以并行 | 独立 agent 可同时跑(如 A4 审查 + B1 剧本写作并行) |

### 1.3 拆 agent 的真正价值不在"每次都跑",而在四件事

1. **复用**:一次配置长期用,10 部小说共用同一个 B1 剧本 agent。
2. **替换**:A2 小说效果不好就只换 A2,下游 A3/B1 不动。
3. **并行**:D3 关键帧 + E1 视频 prompt 同时生成(都基于分镜 + D1 视觉设定集),省一半时间。
4. **隔离上下文**:A4 审查规则不会污染 B1 生成规则。

## Part 2 · 16 个 Agent 清单

### 2.1 完整清单

| # | ID | Agent 名 | 阶段 | 类型 | 输入 | 输出 |
|---|---|---|---|---|---|---|
| 1 | **A1** | 小说大纲 | ② 小说 | 必跑 | 题材 + 集数 + 主角设定(或散文式想法,A1 自动推算-确认) | 全集大纲 |
| 2 | **A2** | 小说正文 | ② 小说 | 必跑 | 大纲 | 完整小说(5k-30k 字) |
| 3 | **A3** | 小说精化 | ② 小说 | 必跑 | 小说初稿 + (可选)A4 采纳清单 | 补人物 / 场景 / 道具的精化版 / 回炉版 |
| 4 | **A4** | 小说审查 | ② 小说 | 可选 | 小说 | 合规 + 爽点审查报告 + 可勾选采纳清单 |
| 4.5 | **A5** | 阅读版导出 | ② 小说 | 旁路 | A2/A3 工程稿 | 去节拍标签的纯阅读稿 |
| 5 | **B1** | 剧本生成(标准 + 类型特化) | ③ 剧本 | 必跑 | 小说 + 资产卡 | 分场剧本 |
| 6 | **B2** | 剧本精简 | ③ 剧本 | 必跑 | 剧本初稿 | 删除冗余 / 压缩台词 |
| 7 | **B3** | 剧本连贯审查 | ③ 剧本 | 可选 | 精简剧本 | 时间线 / 逻辑 / 道具流转审查 |
| 8 | **C1** | 分镜骨架(片段+镜头+时长+占位) | ④ 分镜 | 必跑 | 剧本 + 资产卡 | 分镜骨架(无特效细节) |
| 9 | **C2** | 分镜增强(特效+色温+景别+运镜+重排时长) | ④ 分镜 | 必跑 | C1 骨架 | 增强分镜词 |
| 10 | **C3** | 分镜审查(合规+即梦理解性+台词时长) | ④ 分镜 | 必跑 | C2 增强分镜 | 三层审查报告 |

| 12 | **D2** | 视觉设定集 · 审查(三轮) | ⑤ 故事板 | 必跑 | D1 输出全集 + 元素清点表 + A3 资产卡 | 人物专审 + 5 模块审 + 终审清点核对 + 优先级矩阵 |
| 13 | **D3** | 分镜→故事板(关键帧)prompt | ⑤ 故事板 | 必跑 | 分镜 + A3 文字资产卡 + D1 视觉设定集 | 每镜首帧静态图 prompt |
| 14 | **E1** | 故事板→图生视频 prompt | ⑥ 图生视频 | 必跑 | 故事板首帧图 + 分镜运镜 | 每镜图生视频 prompt(即梦适配) |
| 15 | **F1** | 配音指令生成 | ⑦ 配音 | 必跑 | 剧本台词 + 角色音色档案 | 带 TTS 指令的台词清单 |

> **命名说明(V1.3)**:D1 由"三视图"重命名为"**视觉设定集**",和 A3"文字资产卡"形成清晰对照——同一套设定信息的**文字版** vs **视觉版**。三视图、关键道具 reference、服装变化集都是视觉设定集的具体输出物。
>
> **D1 位置说明(V1.2 调整)**:D1 视觉设定集从"③设定集 / 与 B1 并行"挪到"⑤故事板 / C3 之后 D3 之前"。原因:**分镜词出来后,所有出场角色、所有服装变化(战神揭身份换军装、总裁出席酒会换礼服等)、所有关键道具都已锁定**,此时做视觉设定集可一次到位、不返工;且 D1 直接服务下游 D3 故事板的"角色锚定参考图"功能,信息衰减最小。
>
> **A3 文字资产卡 vs D1 视觉设定集 区别(都不可省)**:
> - **A3 文字资产卡** = 文字版 IR(中间表示),用文字描述每个角色/场景/道具的外观要点。**下游 B1 / B2 / B3 / C1 / C2 / C3 都靠它来保持描述一致**(不能让每个 agent 自己从小说原文重抽),**D1 自己也需要它作为出图 prompt 的描述基础**。删掉它 = 下游所有文本类 agent 都失去统一锚点。
> - **D1 视觉设定集** = 视觉版图像锁,把 A3 的文字描述 + 分镜锁定的服装/道具清单变成可直接喂 MJ / SD / 即梦的绘图 prompt + 出图参考。**下游 D3 故事板用它做角色锚定 reference**。
> - 两者**不冲突、不重复、不能互相替代**——文字版服务文本生成阶段,视觉版服务出图阶段。

### 2.2 哪些步骤没有 agent(及为什么)

| 步骤 | 为什么没 agent |
|---|---|
| ① 选题策划 | 题材选择 + 数据分析,需要人脑 + 平台数据,难以标准化 |
| ⑧ 音乐音效 | 选歌是审美判断,LLM 帮不了核心决策 |
| ⑨ 剪辑后期 | 节奏 / 转场 / 调色是手感活,不是文本任务 |
| ⑩ 发布运营 | 标题 / 封面 / 标签依赖平台理解和数据感觉 |

> 原"③设定集"独立阶段已取消——A3 输出的文字资产卡归入"②小说"阶段衍生物,由用户在 `材料库/人物/`、`材料库/场景/` 等目录建档维护(不需独立 agent);D1 视觉设定集的图像版资产挪到"⑤故事板"阶段。

**这 4 步用"操作指南"代替 agent**,见 `学习笔记/阶段3_单点深入.md`。

### 2.3 必跑 / 可选 / 并行

#### 必跑(每部作品都要,共 13 个)
```
A1 → A2 → A3 → B1 → B2 → C1 → C2 → C3 → D1 → D2 → D3 → E1 → F1
```

#### 可选(看题材和需要,共 2 个)
- **A4 小说审查**:题材敏感(玄幻法宝 / 悬疑犯罪)/ 投平台前。A4 → A3 可循环回炉重写
- **B3 剧本连贯审查**:长剧(20 集以上)/ 改编多次后

#### 旁路工具(不进主流程,按需用,共 1 个)
- **A5 阅读版导出**:把 A2/A3 工程稿(含节拍标签 + 精化标注)转为纯阅读稿,给作者本人或非技术读者看。**不影响下游 B1/C1 等所有用工程稿做输入的 agent**

#### 可并行(节省时间)
- **A4 小说审查** 与 **B1 剧本生成** 可同时跑(一个审、一个先开写)
- **D3 关键帧 prompt** 与 **E1 视频 prompt** 可同时生成(都基于分镜 + D1 视觉设定集)

> **D1 不再与 B1 并行**:V1.2 起 D1 移到 C3 之后,理由是分镜锁定后才知道全角色 + 全服装变化清单,提前并行会返工。

## Part 3 · Agent 文档标准 Schema

每个 agent 的 .md 文件必须遵守以下结构。**自包含**(单独打开就能用,不依赖外部文件)。
**修订记录单独写入 `材料库/agent/CHANGELOG.md`**——agent 文件不带修订记录,避免污染 system prompt。

```markdown
# Agent: <名称>

## Meta
- 版本:V1.0
- 日期:YYYY-MM-DD
- 适用平台:DeepSeek / Claude / 豆包 通用
- 输入:<期待的输入形态,含粒度,如"单集 A2 小说正文 + 世界圣经">
- 输出:<期待的输出形态>

## §0 硬约束(每次响应必读)

### 输出格式
1. **只输出 Markdown 纯文本**。禁止 HTML / JSON / XML / 自定义结构化语法。
2. 禁止把整篇输出包在代码块里。仅引用代码片段时才用代码块。
3. 章节标题用 ## / ###,列表用 - 或 1.,表格用 GFM 语法。
4. 不要装饰性 emoji。手机阅读优先。

### 行为约束
1. **每次只处理用户本轮输入**,处理完即停止。
2. **禁止**主动续写、推测下一轮、反问"是否要 X / 是否继续"。
3. **禁止**越出本 agent §角色定位 职责。越界请求一律回复"本 agent 仅负责 X,请改用 Y"。
4. 输入材料不足时,新起 `## 缺失输入` 列清单。

## 角色定位
你是一个 ...

## 输入约定
**单次执行粒度**(单集 / 单批 N 集 / 全局一次)
{题材}: 玄幻 / 现代都市 / 古风穿越 / ...
{平台}: 抖音 / 视频号 / B 站
{世界圣经}: 必填(per 集类 agent)

## 输出 Schema
(精确描述输出格式:字段、顺序、标点、长度上限)

## 规则
1. ...

## 正例 / 反例
...

## 自检清单
- [ ] ...

## 禁止事项
- ...
```

> **修订记录不放在 agent 文件**——统一到 `材料库/agent/CHANGELOG.md`。理由:(1)避免修订日志当成行为指令污染模型;(2)精简 token 消耗;(3)移动端复制粘贴更轻。

### 关键设计原则

| 原则 | 解释 |
|---|---|
| **自包含** | 单独打开就能用,不依赖外部文件 |
| **变量明示** | 所有可变项用 `{xxx}` 占位 |
| **正反例必须有** | AI 看示例学得比看规则快 |
| **自检清单** | 让 agent 主动质检 |
| **输出长度上限** | 避免无限膨胀 |

## Part 4 · Agent 实际使用方式

### 4.1 平台 1:DeepSeek

#### 方式 A · 网页版"智能体"(推荐)

1. 登录 DeepSeek,进入"智能体"
2. "创建智能体" → 填名称(如 `漫剧-剧本生成-玄幻V1.0`)
3. **系统提示词槽位**:把对应 agent md 整段复制粘贴
4. 保存
5. 之后直接发输入,智能体永久保留

#### 方式 B · 普通对话(一次性)

```
[粘贴 agent md 整段]
---
以上是系统指令,请严格遵守。回复"已就绪"后我会发输入。
```

### 4.2 平台 2:Claude

#### 方式 A · Claude.ai Projects(推荐)

1. 登录 [claude.ai](https://claude.ai) → Create Project
2. Custom instructions 槽位粘贴 agent md
3. 直接发输入,Project 永久保留

#### 方式 B · 普通对话:同 DeepSeek 方式 B

#### 方式 C · Claude API(批量自动化)

```python
import anthropic
client = anthropic.Anthropic(api_key="sk-ant-...")

# 读取 agent prompt
with open("材料库/agent/B1_剧本生成.md", encoding="utf-8") as f:
    system_prompt = f.read()

# 读取输入(小说)
with open("我的作品/003_战神归来/01_小说.md", encoding="utf-8") as f:
    novel = f.read()

# 调用 API
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=16000,
    system=system_prompt,
    messages=[{"role": "user", "content": novel}]
)

# 存输出
with open("我的作品/003_战神归来/03_剧本.md", "w", encoding="utf-8") as f:
    f.write(response.content[0].text)
```

### 4.3 平台 3:豆包(字节)

豆包没有"智能体"功能,只能用方式 B(普通对话每次粘贴 agent md)。
适合**接地气的抖音类题材**,中文最自然。

### 4.4 平台 4:Kimi(月之暗面)

Kimi 支持上传"系统提示词"(类似 Project),适合**长上下文**任务(整本网文导入)。

- **每一步产出立刻存文件**——存到 `我的作品/<项目名>/` 对应位置
- **不满意直接回头改 agent md,重跑**——不要在原对话里反复调试
- **完整使用方法见 `材料库/操作指南.md`**

## Part 6 · 常见避坑

| ❌ 错误做法 | ✅ 正确做法 |
|---|---|
| 把所有 agent 揉进一个对话 | 每个 agent 独立窗口 / 独立 Project |
| 把 agent md 写进 CLAUDE.md(项目规则) | agent md 放 `材料库/agent/`,只在使用时复制到 LLM |
| 用"对话式"语气("你能帮我...?") | 用"指令式" system prompt("你是 X,你必须...") |
| 留对话窗口当存档 | 关闭窗口就丢,**必须存文件入 git** |
| 占位符忘了替换 | 发输入前先替换 `{xxx}` 或在 user message 里明示 |
| 单次效果不好就反复在对话里"再来一次" | 改 agent md,**修复根因**,新对话重跑 |
| 输出没存档,过几天找不到了 | 立即存到 `我的作品/<项目>/0X_*.md` |

## Part 7 · Agent 文件命名约定

**字母前缀按阶段分类,数字按阶段内顺序**:

| 字母 | 阶段 | 字母含义 |
|---|---|---|
| **A** | ② 小说 | A = 阶段二的"二"对应 A 类(小说为流水线起点) |
| **B** | ③ 剧本 | B = 第三阶段顺延 |
| **C** | ④ 分镜 | C = 第四阶段顺延 |
| **D** | ⑤ 故事板(含视觉设定集 + 关键帧) | D = 第五阶段顺延 |
| **E** | ⑥ 图生视频 | E = 第六阶段顺延 |
| **F** | ⑦ 配音 | F = 第七阶段顺延 |
