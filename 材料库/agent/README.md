# Agent 库

> AI 漫剧流水线 10 步中,有 7 步可以**标准化**成可复用的 LLM 系统提示词(system prompt)——这就是 14 个 Agent(A1-A14,按流水线顺序连号)。
> 把它们配置到 DeepSeek / Claude / 豆包,**输入对应素材就能直接出活儿**,不用每次重新写指令。

---

## Part 1 · Agent 是什么、为什么要拆

### 1.1 一句话定义

**Agent** = 一份**喂给 LLM 创建智能体的 system prompt**(.md 文件),让 LLM 在某个生产环节扮演特定角色、用特定方式干活。

**不是项目规则**(CLAUDE.md 那种"和 Claude 协作的工作目录规则")。
**不是对话指令**(临时发的 prompt)。
**是可复用、可版本化、可在不同平台间迁移的工作流**。

### 1.2 为什么把流水线拆成多个 agent,而不是写一段长 prompt 一气呵成

| 长 prompt 一气呵成 | 拆成多个 agent |
|---|---|
| 上下文窗口爆炸 | 每个 agent 只看自己该看的输入 |
| 一处错全盘崩 | 一处错只改一处 |
| 跨平台难复用 | 同一 agent 可跑 DeepSeek / Claude / 豆包 |
| 无法版本化 | 文件即版本,可入 git,可对比 diff |
| 难以并行 | 独立 agent 可同时跑(如 A4 审查 + A5 剧本写作并行) |

### 1.3 拆 agent 的真正价值不在"每次都跑",而在四件事

1. **复用**:一次配置长期用,10 部小说共用同一个 A5 剧本 agent。
2. **替换**:A2 小说效果不好就只换 A2,下游 A3/A5 不动。
3. **并行**:A12 关键帧 + A13 视频 prompt 同时生成(都基于分镜 + A11 视觉设定集),省一半时间。
4. **隔离上下文**:A4 审查规则不会污染 A5 生成规则。

| 14 | **A14** | 配音指令生成 | ⑦ 配音 | 必跑 | 剧本台词 + 角色音色档案 | 带 TTS 指令的台词清单 |

> **命名说明(V1.3)**:A11 由"三视图"重命名为"**视觉设定集**",和 A3"文字资产卡"形成清晰对照——同一套设定信息的**文字版** vs **视觉版**。三视图、关键道具 reference、服装变化集都是视觉设定集的具体输出物。
>
> **A11 位置说明(V1.2 调整)**:A11 视觉设定集从"③设定集 / 与 A5 并行"挪到"⑤故事板 / A10 之后 A12 之前"。原因:**分镜词出来后,所有出场角色、所有服装变化(战神揭身份换军装、总裁出席酒会换礼服等)、所有关键道具都已锁定**,此时做视觉设定集可一次到位、不返工;且 A11 直接服务下游 A12 故事板的"角色锚定参考图"功能,信息衰减最小。
>
> **A3 文字资产卡 vs A11 视觉设定集 区别(都不可省)**:
> - **A3 文字资产卡** = 文字版 IR(中间表示),用文字描述每个角色/场景/道具的外观要点。**下游 A5 / A6 / A7 / A8 / A9 / A10 都靠它来保持描述一致**(不能让每个 agent 自己从小说原文重抽),**A11 自己也需要它作为出图 prompt 的描述基础**。删掉它 = 下游所有文本类 agent 都失去统一锚点。
> - **A11 视觉设定集** = 视觉版图像锁,把 A3 的文字描述 + 分镜锁定的服装/道具清单变成可直接喂 MJ / SD / 即梦的绘图 prompt + 出图参考。**下游 A12 故事板用它做角色锚定 reference**。
> - 两者**不冲突、不重复、不能互相替代**——文字版服务文本生成阶段,视觉版服务出图阶段。

### 2.2 哪些步骤没有 agent(及为什么)

| 步骤 | 为什么没 agent |
|---|---|
| ① 选题策划 | 题材选择 + 数据分析,需要人脑 + 平台数据,难以标准化 |
| ⑧ 音乐音效 | 选歌是审美判断,LLM 帮不了核心决策 |
| ⑨ 剪辑后期 | 节奏 / 转场 / 调色是手感活,不是文本任务 |
| ⑩ 发布运营 | 标题 / 封面 / 标签依赖平台理解和数据感觉 |

> 原"③设定集"独立阶段已取消——A3 输出的文字资产卡归入"②小说"阶段衍生物,由用户在 `材料库/人物/`、`材料库/场景/` 等目录建档维护(不需独立 agent);A11 视觉设定集的图像版资产挪到"⑤故事板"阶段。

**这 4 步用"操作指南"代替 agent**,见 `学习笔记/阶段3_单点深入.md`。

### 2.3 必跑 / 可选 / 并行

#### 必跑(每部作品都要,共 12 个)
```
A1 → A2 → A3 → A5 → A6 → A8 → A9 → A10 → A11 → A12 → A13 → A14
```

#### 可选(看题材和需要,共 2 个)
- **A4 小说审查**:题材敏感(玄幻法宝 / 悬疑犯罪)/ 投平台前
- **A7 剧本连贯审查**:长剧(20 集以上)/ 改编多次后

#### 可并行(节省时间)
- **A4 小说审查** 与 **A5 剧本生成** 可同时跑(一个审、一个先开写)
- **A12 关键帧 prompt** 与 **A13 视频 prompt** 可同时生成(都基于分镜 + A11 视觉设定集)

> **A11 不再与 A5 并行**:V1.2 起 A11 移到 A10 之后,理由是分镜锁定后才知道全角色 + 全服装变化清单,提前并行会返工。

## Part 3 · Agent 文档标准 Schema

每个 agent 的 .md 文件必须遵守以下结构。**自包含**(单独打开就能用,不依赖外部文件)。

```markdown
# Agent: <名称>

## Meta
- 版本:V1.0
- 日期:YYYY-MM-DD
- 适用平台:DeepSeek / Claude / 豆包 通用
- 输入:<期待的输入形态,如"小说原文 5000-30000 字">
- 输出:<期待的输出形态,如"标准格式剧本">

## 角色定位
你是一个 ...

## 输入约定
{题材}: 玄幻 / 现代都市 / 古风穿越 / ...
{平台}: 抖音 / 视频号 / B 站
{集数}: 10 / 20 / 30

## 输出 Schema
(精确描述输出格式:字段、顺序、标点、长度上限)

## 规则
1. ...
2. ...

## 正例
(一段输入 → 一段输出的完整对照样例)

## 反例
(错误写法示范 + 为什么错)

## 自检清单
- [ ] 是否所有对话保留?
- [ ] 是否符合时长控制?

## 禁止事项
- 不得 ...

## 修订记录
- V1.0(YYYY-MM-DD):初版
```

### 关键设计原则

| 原则 | 解释 |
|---|---|
| **自包含** | 单独打开就能用,不依赖外部文件 |
| **变量明示** | 所有可变项用 `{xxx}` 占位 |
| **正反例必须有** | AI 看示例学得比看规则快 |
| **自检清单** | 让 agent 主动质检 |
| **输出长度上限** | 避免无限膨胀 |

## Part 4 · Agent 实际使用方式

### 4.1 平台 1:DeepSeek

#### 方式 A · 网页版"智能体"(推荐)

1. 登录 DeepSeek,进入"智能体"
2. "创建智能体" → 填名称(如 `漫剧-剧本生成-玄幻V1.0`)
3. **系统提示词槽位**:把对应 agent md 整段复制粘贴
4. 保存
5. 之后直接发输入,智能体永久保留

#### 方式 B · 普通对话(一次性)

```
[粘贴 agent md 整段]
---
以上是系统指令,请严格遵守。回复"已就绪"后我会发输入。
```

### 4.2 平台 2:Claude

#### 方式 A · Claude.ai Projects(推荐)

1. 登录 [claude.ai](https://claude.ai) → Create Project
2. Custom instructions 槽位粘贴 agent md
3. 直接发输入,Project 永久保留

#### 方式 B · 普通对话:同 DeepSeek 方式 B

#### 方式 C · Claude API(批量自动化)

```python
import anthropic
client = anthropic.Anthropic(api_key="sk-ant-...")

# 读取 agent prompt
with open("材料库/agent/A5_剧本生成.md", encoding="utf-8") as f:
    system_prompt = f.read()

# 读取输入(小说)
with open("我的作品/003_战神归来/01_小说.md", encoding="utf-8") as f:
    novel = f.read()

# 调用 API
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=16000,
    system=system_prompt,
    messages=[{"role": "user", "content": novel}]
)

# 存输出
with open("我的作品/003_战神归来/03_剧本.md", "w", encoding="utf-8") as f:
    f.write(response.content[0].text)
```

### 4.3 平台 3:豆包(字节)

豆包没有"智能体"功能,只能用方式 B(普通对话每次粘贴 agent md)。
适合**接地气的抖音类题材**,中文最自然。

### 4.4 平台 4:Kimi(月之暗面)

Kimi 支持上传"系统提示词"(类似 Project),适合**长上下文**任务(整本网文导入)。

### 关键纪律

- **每个 agent 用独立对话窗口**——避免上下文污染
- **每一步产出立刻存文件**——存到 `我的作品/<项目名>/` 对应位置
- **不满意直接回头改 agent md,重跑**——不要在原对话里反复调试

## Part 6 · 常见避坑

| ❌ 错误做法 | ✅ 正确做法 |
|---|---|
| 把所有 agent 揉进一个对话 | 每个 agent 独立窗口 / 独立 Project |
| 把 agent md 写进 CLAUDE.md(项目规则) | agent md 放 `材料库/agent/`,只在使用时复制到 LLM |
| 用"对话式"语气("你能帮我...?") | 用"指令式" system prompt("你是 X,你必须...") |
| 留对话窗口当存档 | 关闭窗口就丢,**必须存文件入 git** |
| 占位符忘了替换 | 发输入前先替换 `{xxx}` 或在 user message 里明示 |
| 单次效果不好就反复在对话里"再来一次" | 改 agent md,**修复根因**,新对话重跑 |
| 输出没存档,过几天找不到了 | 立即存到 `我的作品/<项目>/0X_*.md` |

1. 阅读 `Part 3 · Agent 文档标准 Schema`
2. 在本目录新建 `A<编号>_<功能名>.md`
3. 按 Schema 填写所有字段
4. **拿 1-2 部你喜欢的作品作为"正例"**(贴一段你认可的输入 → 输出)
5. 上 DeepSeek / Claude 创建智能体测试
6. 跑 5-10 次,记录不满意的地方
7. 改 agent md,迭代到 V1.1 / V1.2 / V2.0
8. **建配套的 SOP**(放在 `材料库/SOP/`)讲怎么和其他 agent 配合用
