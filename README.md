## 0. 总览

```
ManJu_Learn/
├── README.md
├── 01_学习笔记/
├── 02_提示词库/
├── 03_角色与世界观/
├── 04_风格参考/
├── 05_工具笔记/
├── 06_项目作品/
├── 07_资源链接/
├── 99_草稿区/
└── .gitignore
```

设计原则：

- **数字前缀** —— 按学习与生产管线顺序强制排序。
- **"学习"与"产出"分离** —— `01~05` 是知识库（可复用），`06` 是具体作品，`07/99` 是辅助。
- **"模板"与"案例"两层** —— `templates/` 是抽象骨架，`examples/` 是具体成功 prompt。
- **大文件不进 git** —— 工程文件、原始视频、PSD 走 `.gitignore` 或 Git LFS。
- **框架自身可演进** —— 目录结构本身也有版本号，扩张时升级 V1.x → V2.x（详见 §14）。

## 1. README.md

**这是什么**
仓库门户（即本文件）。包含：仓库目的、学习路线图（自己当前学到第几阶段、下一步学什么）、目录索引、常用入口链接。

**什么时候动它**

- 仓库初建时写一次。
- 每完成一个学习阶段、调整一次目录结构时更新。

**示例场景**
今天你看完一套"AI 漫剧从 0 到变现"的课程，把你新掌握的能力点更新到 README 的"学习路线图"里，标记"分镜表生成"为已掌握。

### 学习路线图（动态更新）

- [ ] 阶段 1：跑通端到端最小成片（一个 30 秒短片）

## 2. 01_学习笔记/

**这是什么**
个人学习产出，第一手知识沉淀。**不是别人的提示词**（那是 `02_`），也**不是项目复盘**（那是 `06_<项目>/07_复盘.md`），是你脑子里整理出来的"我学到了什么"。

**子目录**

```
01_学习笔记/
├── 工作流总览.md        端到端生产管线：小说→剧本→分镜→图片→视频→剪辑
├── 未知与待探索.md      听说过但还没搞懂的概念清单（V1.1 新增，详见 §13）
├── 基础概念/            AI 漫剧的商业模式、平台规则、爆款公式
├── 教程笔记/            按课程或 UP 主组织：<来源>_<主题>.md
└── 复盘日志/            YYYYMMDD_<主题>.md，每次实操后的反思
```

**什么时候用**

- 看完一节课、读完一篇文章，把要点用自己话复述一遍 → `教程笔记/`
- 做完一个小练习（比如今天试了 5 种人物 prompt 对比效果） → `复盘日志/20260520_人物prompt对比.md`
- 第一次想清楚"AI 漫剧到底怎么从 0 做到成片"的全流程 → `工作流总览.md`
- 听到一个陌生术语但暂时没空深入 → `未知与待探索.md`

**示例场景**
今天看了 B 站某 UP 主讲"如何让分镜更有电影感"的视频，做了 30 分钟笔记 → 放在 `01_学习笔记/教程笔记/某UP主_分镜电影感.md`。注意：视频里给的具体 prompt **不放这里**，放在 `02_提示词库/30_剧本转分镜/examples/` 并互相引用。

## 3. 02_提示词库/

**这是什么**
仓库的核心资产。所有"可复用的"提示词都在这里，按生产管线阶段编号。

每个子目录都是 `templates/`（模板骨架）+ `examples/`（具体成功案例）的双层结构。

```
02_提示词库/
├── 00_提示词写作方法论.md   通用 prompt engineering 心法
├── 10_小说创作/
├── 20_小说转剧本/
├── 30_剧本转分镜/
├── 40_人物图片/
├── 50_场景图片/
├── 60_视频生成/
└── 70_配音配乐/
```

### 3.1 templates/ 与 examples/ 的区别

| | templates/ | examples/ |
|---|---|---|
| 内容 | 抽象骨架，带占位符 `{角色名}` `{动作}` | 具体一次成功的完整 prompt |
| 目的 | 下次直接套用 | 启发灵感、对比效果 |
| 文件名 | `人物全身正面_模板.md` | `20260520_少女白衣古风_即梦v3.md` |

### 3.2 各子目录详解

#### 00_提示词写作方法论.md
你自己总结的 prompt 通用规律：权重写法、负面词、结构顺序、风格词位置等。

**示例场景**：今天发现"把镜头描述放最前面"出图更稳，把这条经验补充进来。

#### 10_小说创作/
小说本身（不是剧本）的生成 prompt：选题、大纲、章节、人物对白。

**示例场景**：你试出一个"3 章短篇爽文大纲生成器" prompt → `10_小说创作/templates/短篇爽文大纲_模板.md`。

#### 20_小说转剧本/
把小说改写成剧本格式（场景标题、角色、对白、动作描述）的 prompt。

**示例场景**：找到一个能稳定输出标准剧本格式的 prompt → `20_小说转剧本/templates/标准剧本格式化_模板.md`。

#### 30_剧本转分镜/
把剧本拆成镜头表（镜号、景别、运镜、画面描述、台词、时长）的 prompt。

**示例场景**：拆解了某爆款作品的分镜风格 → `30_剧本转分镜/examples/拆解_某爆款_悬疑分镜.md`。

#### 40_人物图片/
**人物**生成 prompt（人物三视图、表情、动作、服装变化）。

```
40_人物图片/
├── templates/           按场景类型分：全身/半身/特写、正/侧/背
├── style_keywords.md    画风/光影/材质关键词速查表
└── examples/            一次成功的完整 prompt
```

**示例场景**：
你今天在 X 上看到一个博主发的"赛博朋克少女" prompt 效果惊艳 →

1. 拷贝完整 prompt 到 `40_人物图片/examples/20260520_赛博朋克少女_来源X博主.md`
2. 文件头标注：来源链接、使用工具、出图截图、为什么好
3. 如果它具有可复用骨架（比如"光影描述+材质描述+构图"的结构），抽出骨架放到 `40_人物图片/templates/赛博风格人物_模板.md`
4. 把里面的特色风格词补充进 `style_keywords.md`

#### 50_场景图片/
**场景**生成 prompt（室内/室外、远中近景、白天夜晚、天气）。结构同 `40_`。

**示例场景**：你需要一张"雨夜霓虹小巷"，试出一个稳定 prompt → `50_场景图片/examples/雨夜霓虹小巷_可灵.md`。

#### 60_视频生成/
图生视频 / 文生视频 prompt，按镜头语言拆分：

```
60_视频生成/
├── 运镜.md     推/拉/摇/移/跟/升降镜头的 prompt 写法
├── 转场.md     硬切/淡入淡出/匹配剪辑/动作衔接
└── 特效.md     爆炸/粒子/慢动作/光效
```

**示例场景**：你看到别人用"匹配剪辑"做了惊艳转场 → `60_视频生成/转场.md` 里新增"匹配剪辑"小节，附 prompt 和案例链接。

#### 70_配音配乐/
TTS 情绪标签写法、Suno/Udio 的 BGM 描述 prompt、口型同步技巧。

**示例场景**：摸索出一套"少女角色温柔语气"的 ElevenLabs 参数组合 → `70_配音配乐/templates/少女温柔_ElevenLabs参数.md`。

## 4. 03_角色与世界观/

**这是什么**
**人物一致性**的核心资产库。AI 漫剧最大的痛点是"同一个角色每次生成长得不一样"，解决办法是给每个角色一份"角色卡"，每次生成都附上固定 prompt 块。

```
03_角色与世界观/
├── characters/
│   └── <角色名>/
│       ├── character_card.md   外貌锚点、服装、性格、口癖、年龄
│       ├── reference/          首图、三视图、表情包（PNG）
│       └── seed_prompts.md     每次生成必带的固定 prompt 块
├── worlds/                     世界观设定（时代、地理、势力、规则）
└── style_guide.md              整部剧的视觉与语言基调
```

**与 `02_提示词库/40_人物图片/` 的区别**

| | 03_角色与世界观/ | 02_提示词库/40_人物图片/ |
|---|---|---|
| 性质 | 具体角色的"身份证" | 通用的人物生成方法库 |
| 复用 | 跨集复用同一个角色 | 任何角色都可套用模板 |
| 例子 | "林小满"的固定外貌 prompt | "古风少女全身像"模板 |

**示例场景**

- 启动一个新项目，主角"林小满"定型 → 在 `characters/林小满/` 建目录，写 `character_card.md`，把第一张定稿图放进 `reference/`，从这张图反推出 `seed_prompts.md`。
- 之后所有涉及林小满的镜头，都直接 `cat seed_prompts.md` 拼到 prompt 前。
- 你定下整部剧用"宫崎骏画风+暖色调" → 写入 `style_guide.md`，每次都引用。

## 5. 04_风格参考/

**这是什么**
别人的优秀作品、参考图、拆解笔记。**输入型**资料——你从外部世界收集进来用于启发的素材。

```
04_风格参考/
├── visual_refs/    收藏的参考图（按风格分子目录：赛博/古风/治愈/悬疑...）
├── 优秀作品/       别人的爆款：链接 + 截图 + 一句话点评
└── 拆解笔记/       某爆款的结构、节奏、镜头语言拆解
```

**与 `02_提示词库/.../examples/` 的区别**

- `examples/` 是**你自己**试出来的成功 prompt（有完整 prompt 文本）。
- `04_风格参考/` 是**别人**的成品（通常你只有截图，拿不到原始 prompt）。

**示例场景**

- 在小红书看到一组"治愈系咖啡馆"插画很喜欢 → 截图存进 `visual_refs/治愈/`，文件名记录来源。
- 抖音刷到一个 500w 赞的 AI 漫剧 → 链接和截图进 `优秀作品/`，认真拆解的话再写一份 `拆解笔记/<作品名>_拆解.md`。

## 6. 05_工具笔记/

**这是什么**
每个工具的使用心得、参数、踩坑记录。**工具维度**组织（横切各个生产阶段）。

```
05_工具笔记/
├── 即梦.md
├── 可灵.md
├── Midjourney.md
├── Runway.md
├── Suno.md
├── ElevenLabs.md
├── 剪映_CapCut.md
└── 工具对比表.md       横向对比、什么场景用什么工具
```

**与 `02_提示词库/` 的区别**

- `02_` 按**生产阶段**组织（不管用什么工具，只要是"生成人物"就放 `40_`）。
- `05_` 按**工具**组织（不管做什么，只要是"用即梦"就放这里）。

如果一条 prompt 强依赖某工具语法（比如 Midjourney 的 `--ar 16:9 --niji 6`），优先放 `02_` 的 examples 里并在文件名标注工具，同时在 `05_工具笔记/Midjourney.md` 里补一条"语法心得"。

**示例场景**

- 今天发现可灵 1.6 的"首尾帧"功能能稳定转场 → `05_工具笔记/可灵.md` 新增一节。
- 比较了即梦和 Midjourney 出图差异 → 更新 `工具对比表.md`。

## 7. 06_项目作品/

**这是什么**
你**实际产出**的作品。每个项目一个独立子目录，完整自包含。

```
06_项目作品/
└── <项目名>/
    ├── 00_企划.md            选题、目标平台、受众、目标数据
    ├── 01_小说/              小说原文（.md）
    ├── 02_剧本/              剧本（.md）
    ├── 03_分镜表.md          镜号/景别/运镜/画面/台词/时长
    ├── 04_素材/
    │   ├── images/          生成的人物与场景图
    │   ├── videos/          生成的视频片段
    │   └── audio/           配音、BGM
    ├── 05_工程/              剪辑工程（建议 .gitignore 或 LFS）
    ├── 06_成片/              导出版本：v1.mp4, v2_修正配音.mp4
    └── 07_复盘.md            数据表现、做对了什么、下次改进
```

**与知识库（01~05）的关系**

- 项目从知识库**取用**（引用模板、套角色卡、用工具笔记里的技巧）。
- 项目沉淀**反哺**知识库（项目里试出的好 prompt → `02_/.../examples/`，新发现的工具技巧 → `05_工具笔记/`，复盘心得 → `01_学习笔记/复盘日志/`）。

**示例场景**

- 启动新项目"机甲少女第一集" → `06_项目作品/机甲少女_EP01/`，先写 `00_企划.md`。
- 项目里用到的"林小满"角色 → 不在项目里重写设定，而是引用 `03_角色与世界观/characters/林小满/seed_prompts.md`。
- 项目做完了，过程中试出一个超好用的"机甲战斗运镜" prompt → 复制到 `02_提示词库/60_视频生成/运镜.md` 让它变成可复用资产。

## 9. 99_草稿区/

**这是什么**
临时的、未归档的、灵感型的内容。**收件箱**，不是终点。

**规则**

- 任何想不清楚放哪儿的内容先扔这里，别因为"分类困难"就不记。
- 每周清理一次，把成熟的内容归位到正式目录，过时的删除。

**示例场景**
洗澡时想到一个"穿越成 NPC"的故事点子，立刻打开 → `99_草稿区/20260520_穿越NPC点子.md`，三句话写完。下周整理时如果决定做，就升级成 `06_项目作品/穿越NPC/00_企划.md`。

## 12. 推荐使用节奏

1. **每天**：草稿区随手记 + 当天产出归位（不留尾巴到第二天）。
2. **每周**：
   - 清理 `99_草稿区/`，更新 `01_学习笔记/复盘日志/` 周总结。
   - **扫一遍 `01_学习笔记/未知与待探索.md`，挑 1~2 项深入**（V1.1 新增）。
3. **每月**：检查 `02_提示词库/` 里哪些 examples 已经稳定到可以抽成 templates；更新本 README 里的学习路线图。
4. **每个项目结束**：必写 `06_项目作品/<项目>/07_复盘.md`，把可复用资产反哺到知识库。

## 13. 未知与待探索机制（V1.1 新增）

学习初期一定会遇到"听过但还没懂"的概念，硬塞进目录会污染分类。引入显式的未知清单：

```
01_学习笔记/
└── 未知与待探索.md
```

**用法**

- 任何陌生术语（ControlNet / LoRA / AnimateDiff / 工作流节点…）→ 立刻加一行，附来源链接。
- 每周扫一遍，挑 1~2 个深入学习；搞懂后**从清单中删除**，笔记归位到 `教程笔记/` 或 `05_工具笔记/`。
- 文件应保持"流动"：只增也只减，不会无限增长。

**示例格式**

```markdown
## 高优先级
- [ ] **ControlNet** —— 控制人物姿势/构图，来源：<某教程链接>，2026-05-20 记

## 中优先级
- [ ] **LoRA 训练** —— 自训练专属画风

## 低优先级 / 等再说
```

## 14. 三级升级路径与框架版本化（V1.1 新增）

未知内容的归档遵守"草稿区 → 未知清单 → 新目录"三级升级：

| 阶段 | 出现频次 | 归档位置 |
|---|---|---|
| 偶尔出现一次的陌生内容 | 1 次 | `99_草稿区/` |
| 反复出现、是独立主题 | 2~3 次 | `01_学习笔记/未知与待探索.md` |
| 已学懂、有 3 篇以上内容要存 | 稳定主题 | **升级目录框架版本**，新增子目录 |

**框架自身的版本化规则**

- 兼容性扩张（新增子目录、补充说明）→ V1.x。
- 重大重构（调整顶层目录、改变设计原则）→ V2.x。
- 每次升级，旧版本作为历史快照保留，不覆盖。
- **新版本必须包含旧版本的全部内容**，再在其上修改与新增。
